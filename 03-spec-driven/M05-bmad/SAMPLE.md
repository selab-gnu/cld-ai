# 예제 실행 및 확인 — 할 일 관리 앱 사용 가이드

> 이 문서는 BMAD로 **완성한 할 일 관리 앱을 실행하고, 직접 써 보고, 스펙(`SPEC.md`)대로 동작하는지 확인하는 방법**을 안내한다.
> 앱을 만드는 과정(설치 → bmad-spec → 스토리 나누기 → bmad-build)은 [GUIDE.md](GUIDE.md) 를 따른다.

**시작 조건**: [GUIDE.md](GUIDE.md) 6단계(스토리 1~3 `/bmad-build`)까지 마쳐서 `my-todo-bmad` 폴더에 앱 코드가 생긴 상태

| 표시 | 하는 곳 |
| --- | --- |
| 🖥️ **터미널** | macOS 터미널 (`my-todo-bmad` 폴더 안) |
| 🌐 **브라우저** | Chrome / Safari 등 |
| 🤖 **Claude Code** | 문제가 있을 때 수정 요청 (`/bmad-build`, `/bmad-spec`, `/bmad-help`) |

> 📝 화면 문구와 배치는 BMAD가 만든 코드에 따라 다르다. **같은 기능이 스펙대로 동작하면 통과**로 본다. `SPEC.md` 의 각 Capability **success** 조건과 GUIDE 4단계에서 답한 열린 질문(키 이름, 안내 문구 등)과 비교하며 확인하면 좋다.

## 1단계: 실행 전 파일과 이력 확인

🖥️ **터미널**

```bash
cd ~/git/my-todo-bmad
ls -a
ls src tests
ls -a _bmad-output/specs/spec-todo-app _bmad-output/specs/spec-todo-app/stories
```

✅ **확인** — 아래와 같은 파일이 있으면 실행할 준비가 된 것이다. (파일 이름은 BMAD가 조금 다르게 만들 수 있다)

```
.claude  .git  _bmad  _bmad-output  index.html  package.json  src  tests
src:    app.js  storage.js  todo.js  style.css
tests:  todo.test.js
_bmad-output/specs/spec-todo-app:          .memlog.md  SPEC.md  stories  stories.yaml
_bmad-output/specs/spec-todo-app/stories:  1-….md  2-….md  3-….md
```

| 파일 | 역할 |
| --- | --- |
| `index.html` | 앱 화면 |
| `src/todo.js` | 추가·완료·삭제·필터 같은 **핵심 로직** (테스트 대상) |
| `src/storage.js` | 브라우저 localStorage 저장·불러오기 |
| `src/app.js` | 화면 그리기와 버튼·키보드 이벤트 |
| `tests/todo.test.js` | 핵심 로직 자동 테스트 |
| `_bmad-output/specs/spec-todo-app/SPEC.md` | **확인 기준** — 아래 시나리오는 이 문서의 `CAP-N` success 조건과 대응한다 |
| `…/stories/N-….md` | 스토리별 계획·구현 기록 (`status: done`) |

### 1-1. BMAD다운 점 — 스토리마다 남은 커밋

```bash
git log --oneline
grep -h "^status:" _bmad-output/specs/spec-todo-app/stories/*.md
```

✅ **확인**

```
e5f6a7b feat: complete filters, remaining count and keyboard access   ← 예시
c3d4e5f feat: add localStorage persistence and basic todo UI
a1b2c3d feat: implement todo core logic with node:test unit tests
8b9c0d1 docs: add todo-app spec and stories
2a3b4c5 chore: install BMAD Method v6
…
status: done
status: done
status: done
```

- [ ] 스토리 1·2·3 에 해당하는 **conventional 커밋**(`feat: …`)이 하나씩 있다. (리뷰 수정 커밋이 더 있을 수 있다)
- [ ] 스토리 문서 3개의 `status` 가 모두 `done` 이다.

```bash
git show --stat HEAD~1      # 커밋 하나에서 바뀐 파일 보기
```

### 1-2. 스펙이 어디서 구현되었는지 따라가기

```bash
grep -n "CAP-[0-9]" _bmad-output/specs/spec-todo-app/SPEC.md | head      # Capability 목록
grep -rln "CAP-4" _bmad-output/specs/spec-todo-app/                       # CAP-4(필터)를 다룬 스토리·문서
cat _bmad-output/specs/spec-todo-app/stories.yaml                          # 스토리 순서와 설명
```

- [ ] Capability 하나(예: `CAP-4` 필터)를 골라 **SPEC.md → stories.yaml → 스토리 문서 → 커밋** 으로 따라갈 수 있다.
- [ ] 스토리 문서의 `baseline_commit` 으로 그 스토리가 바꾼 범위를 볼 수 있다: `git diff <baseline_commit> <다음 커밋> --stat`

## 2단계: 자동 테스트 실행

🖥️ **터미널**

```bash
node --test
```

✅ **기대 출력** (마지막 부분)

```
# tests 24        ← 테스트 개수는 BMAD가 만든 만큼 (예시)
# pass 24
# fail 0
```

- `# fail 0` 이면 핵심 로직이 정상이다.
- `Cannot find package 'vitest'` 같은 오류가 나면 구현이 스펙의 Constraints 를 어긴 것이다. [GUIDE 부록 B](GUIDE.md#부록-b-자주-겪는-문제) 를 참고한다.
- 실패가 있으면 출력 전체를 복사해 Claude Code에 붙여 넣는다.

🤖 **Claude Code**

```text
/clear
```

```text
/bmad-build node --test 결과가 아래와 같아. 원인을 찾아 고쳐 줘. 기준은 _bmad-output/specs/spec-todo-app/SPEC.md 야.
(테스트 출력 붙여 넣기)
```

## 3단계: 앱 실행

🖥️ **터미널**

```bash
python3 -m http.server 8000
```

`Serving HTTP on :: port 8000 …` 이 보이면 서버가 켜진 것이다. 이 터미널은 **그대로 둔다.**

🌐 **브라우저** — 주소창에 입력

```
http://localhost:8000
```

> ⚠️ `index.html` 을 Finder에서 더블클릭해서 열면(`file://…`) 화면이 비어 보인다. 반드시 서버 주소로 연다.

앱 사용을 마치면 서버 터미널에서 `Ctrl + C` 로 끈다.

## 4단계: 화면 둘러보기

처음 열면 할 일이 하나도 없는 빈 목록이 보인다. 화면에는 다음 요소가 있어야 한다. (배치와 문구는 GSD가 만든 디자인에 따라 다르다)

```
┌──────────────────────────────────────────┐
│  할 일 목록                                │
│  ┌──────────────────────────┐ ┌──────┐   │
│  │ 할 일을 입력하세요          │ │ 추가 │   │  ← ① 입력란 + 추가 버튼
│  └──────────────────────────┘ └──────┘   │
│  0/200   (안내 문구 자리)                   │  ← ② 글자 수 · 안내 문구
│  [전체] [진행 중] [완료]   남은 할 일 0개     │  ← ③ 필터 · ④ 남은 개수
│                                          │
│  ☐ (할 일 목록이 여기에 표시)       [삭제]  │  ← ⑤ 체크 상자 · 내용 · 삭제 버튼
└──────────────────────────────────────────┘
```

| 번호 | 요소 | 하는 일 |
| --- | --- | --- |
| ① | 입력란 + 추가 버튼 | 새 할 일 입력. **Enter** 로도 추가 |
| ② | 글자 수 · 안내 문구 | `N/200`, 빈 입력·200자 초과·중복 안내 (GUIDE 4단계에서 정한 방식) |
| ③ | 필터 | 전체 / 진행 중 / 완료 |
| ④ | 남은 할 일 | 완료하지 않은 할 일 수. **필터와 상관없이 전체 기준** |
| ⑤ | 할 일 항목 | 체크 상자(완료) · 내용 · 삭제 버튼 |

✅ **확인**
- [ ] ①~⑤ 요소가 모두 보인다.
- [ ] 이미 할 일이 보이면 예전에 같은 주소로 쓰던 데이터다. 6단계의 **데이터 초기화**를 먼저 한다.

## 6단계: 저장된 데이터 직접 들여다보기

앱이 데이터를 **브라우저 안(localStorage)에만** 저장하는지 확인한다.

어떤 키 이름을 쓰는지 먼저 코드에서 확인한다. (GUIDE 4단계에서 `my-todo-bmad:todos` 로 정했다면 그 이름)

🖥️ **터미널**

```bash
grep -n "localStorage\|KEY" src/storage.js
```

🌐 **브라우저 (Chrome 기준)**

1. 앱 화면에서 **⌘ + ⌥ + I** (개발자 도구)
2. **Application** 탭 → 왼쪽 **Storage › Local storage › http://localhost:8000**
3. 위에서 확인한 키와 JSON 값이 보인다. (예시)

```json
[{"id":3,"text":"운동하기","completed":false},{"id":5,"text":"빨래하기","completed":true}]
```

> Safari: 설정 › 고급 › "웹 개발자용 기능 보기" 켜기 → **⌥ + ⌘ + I** → **저장 공간** 탭

**외부 전송 확인** — **Network** 탭을 열고 새로 고침한 뒤 할 일을 추가·체크·삭제해 본다.

**저장 데이터 손상 확인** — **Console** 탭에서 (`<키>` 는 위에서 확인한 이름)

```js
localStorage.setItem('<키>', 'abc'); location.reload();
```

**데이터 초기화** — **Console** 탭에서

```js
localStorage.clear(); location.reload();
```

✅ **확인**
- [ ] 화면의 할 일과 localStorage 의 JSON 내용이 일치한다.
- [ ] Network 탭에 `localhost` 밖으로 나가는 요청이 없다.
- [ ] 손상 데이터를 넣어도 앱이 멈추지 않고 빈 목록으로 시작한다. (GUIDE 4단계 결정)
- [ ] 초기화 후 빈 목록, 남은 할 일 `0` 으로 돌아간다.

## 7단계: 요구사항과 다를 때 고치기

5·6단계에서 다르게 동작한 것이 있으면, 상황에 맞는 GSD 명령으로 고친다.

| 상황 | 쓰는 명령 | 결과 |
| --- | --- | --- |
| 단계 검증 중이다 (아직 `/gsd-verify-work` 를 하지 않았거나 다시 하는 중) | **`/gsd-verify-work 1`** 에서 "아니요" + 증상 | GSD가 원인을 진단하고 **수정 계획**을 만든다 → `/gsd-execute-phase 1` |
| 원인을 모르는 버그 | **`/gsd-debug 증상`** | 디버거 에이전트가 원인을 찾고 고친다. 상태가 남아 `/clear` 후에도 이어짐 |
| 요구사항 자체를 바꾸거나 작은 기능 추가 | **`/gsd-quick 요청`** | 작은 계획 → 실행 → 커밋 |

🤖 **Claude Code** — 예: 코드가 요구사항과 다를 때

```text
/clear
```

```text
/gsd-debug 진행 중 필터에서 할 일을 체크해도 목록에서 사라지지 않아(시나리오 F4). REQUIREMENTS.md 의 필터 요구사항대로 고치고, 이 경우를 잡는 테스트도 node --test 로 추가해 줘.
```

🤖 **Claude Code** — 예: 동작을 바꾸고 싶을 때

```text
/gsd-quick 완료한 할 일은 목록 맨 아래로 내려가도록 바꿔 줘. 테스트도 추가해 줘.
```

## 8단계: (도전) 마감일 기능 써 보기

[GUIDE.md 9단계](GUIDE.md#9-단계-도전-마감일-기능-빠르게-추가--gsd-quick)에서 `/gsd-quick --full` 로 마감일 기능을 추가했다면 아래를 확인한다. 서버를 다시 켜고 **⌘ + Shift + R** (강력 새로 고침)로 연다.

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| U1 | 기존에 있던 `운동하기` 확인 | 마감일 없이 그대로 보임 (기존 데이터 호환) |
| U2 | `보고서 제출` 입력, 마감일을 **내일**로 선택 후 추가 | 할 일 옆에 마감일 표시 |
| U3 | `세금 납부` 입력, 마감일을 **어제**로 선택 후 추가 | 지난 마감으로 **눈에 띄게 표시** |
| U4 | `세금 납부` 체크 | 완료되면 지난 마감 강조가 사라지거나 약해짐 (결정에 따라) |
| U5 | 마감일 없이 `물 마시기` 추가 | 정상 추가 |
| U6 | **마감일 순 정렬** 선택 | `세금 납부`(어제) → `보고서 제출`(내일) 순, 마감일 없는 항목은 논의에서 정한 위치 |
| U7 | 새로 고침 | 마감일이 유지됨 |

✅ **확인**
- [ ] U1~U7 이 모두 기대대로 동작한다.
- [ ] 6단계 방법으로 보면 마감일이 `YYYY-MM-DD` 형식으로 저장되어 있다.
- [ ] 5단계 시나리오도 다시 해 보니 그대로 동작한다. (기존 기능이 깨지지 않음)
- [ ] `node --test` 가 `# fail 0` 이다.
- [ ] `.planning/quick/` 아래에 이번 작업 폴더가 있고, `git log` 에 마감일 관련 커밋이 따로 있다.

## 문제 해결

| 증상 | 해결 |
| --- | --- |
| 화면이 비어 있다 | `file://` 로 열었는지 확인. `python3 -m http.server 8000` 후 `http://localhost:8000`. 그래도 비면 `/gsd-debug` 에 증상과 콘솔 오류 전달 |
| `Address already in use` | 8000 포트 사용 중. `python3 -m http.server 8080` 후 `http://localhost:8080` |
| 코드를 고쳤는데 화면이 그대로다 | 브라우저 캐시. **⌘ + Shift + R** |
| 새로 고침하면 데이터가 사라진다 | 시크릿 창이 아닌지 확인. 일반 창에서도 사라지면 시나리오 번호(P1 등)와 함께 `/gsd-debug` |
| `node --test` 에서 `Cannot use import statement` | `package.json` 에 `"type": "module"` 이 있는지 확인 |
| `node --test` 가 테스트를 못 찾거나 `vitest` 를 찾는다 | 테스트가 `tests/*.test.js` 에 있고 `node:test` 를 쓰는지 확인. Vitest 로 만들어졌다면 `/gsd-quick 테스트를 node --test 로 바꿔 줘` |
| 개발자 도구 Console 에 빨간 오류가 있다 | 오류를 복사해 `/gsd-debug 브라우저 콘솔 오류야: …` |
| 어디까지 했는지 모르겠다 | 🤖 `/gsd-progress` |
| 화면 문구·배치가 이 문서 그림과 다르다 | 정상이다. **기능(5단계 시나리오)이 같으면** 통과 |
