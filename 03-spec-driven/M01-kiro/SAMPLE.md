# 예제 실행 및 확인 — 할 일 관리 앱 사용 가이드

> 이 문서는 Kiro로 **완성한 할 일 관리 앱을 실행하고, 직접 써 보고, 요구사항(requirements.md)대로 동작하는지 확인하는 방법**을 안내한다.
> 앱을 만드는 과정(설치 → 스티어링 → Spec → 작업 실행)은 [GUIDE.md](GUIDE.md) 를 따른다.

**시작 조건**: [GUIDE.md](GUIDE.md) 6단계(작업 실행)까지 마쳐서 `my-todo-kiro` 폴더에 앱 코드가 생기고, `.kiro/specs/todo-list/tasks.md` 의 작업이 모두 완료된 상태

| 표시 | 하는 곳 |
| --- | --- |
| 🖥️ **터미널** | Kiro 안의 터미널 (**Terminal › New Terminal**) 또는 macOS 터미널, `my-todo-kiro` 폴더 |
| 🌐 **브라우저** | Chrome / Safari 등 |
| 👻 **Kiro 채팅** | 문제가 있을 때 수정 요청 (`#spec:todo-list` 로 Spec을 불러와서) |

> 📝 화면 문구와 배치는 Kiro가 만든 코드에 따라 다르다. **같은 기능이 요구사항대로 동작하면 통과**로 본다.

## 1단계: 실행 전 파일 확인

🖥️ **터미널**

```bash
cd ~/git/my-todo-kiro
ls -a
ls src tests .kiro .kiro/specs/todo-list
```

✅ **확인** — 아래와 같은 파일이 있으면 실행할 준비가 된 것이다. (파일 이름은 Kiro가 조금 다르게 만들 수 있다)

```
.git  .kiro  index.html  package.json  src  tests
src:    app.js  storage.js  style.css  todo.js
tests:  todo.test.js
.kiro:  hooks  specs  steering
.kiro/specs/todo-list:  design.md  requirements.md  tasks.md
```

| 파일 | 역할 |
| --- | --- |
| `index.html` | 앱 화면 (브라우저로 여는 파일) |
| `src/todo.js` | 할 일 추가·완료·삭제·필터 같은 **핵심 로직** (테스트 대상) |
| `src/storage.js` | 브라우저 localStorage 저장·불러오기 |
| `src/app.js` | 화면 그리기와 버튼·키보드 이벤트 처리 |
| `tests/todo.test.js` | 핵심 로직 자동 테스트 |
| `.kiro/specs/todo-list/requirements.md` | **확인 기준** — 아래 시나리오는 이 문서의 인수 조건과 대응한다 |

> 💡 `requirements.md` 를 Kiro 편집기에 열어 두고 시나리오와 하나씩 비교하며 확인하면 좋다.

## 2단계: 자동 테스트 실행

🖥️ **터미널**

```bash
node --test
```

✅ **기대 출력** (마지막 부분)

```
# tests 20        ← 테스트 개수는 Kiro가 만든 만큼 (예시)
# pass 20
# fail 0
```

- `# fail 0` 이면 핵심 로직이 정상이다.
- 실패가 있으면 출력 전체를 복사해 Kiro 채팅에 붙여 넣는다.

👻 **Kiro 채팅**

```text
#spec:todo-list node --test 결과가 아래와 같아. 요구사항 기준으로 원인을 찾아 고쳐 줘.
(테스트 출력 붙여 넣기)
```

### 2-1. (GUIDE 7단계를 마쳤다면) Hook 자동 실행 확인

👻 **Kiro 채팅**

```text
src/todo.js 맨 위에 "할 일 데이터를 다루는 순수 함수 모음" 이라는 주석을 한 줄 추가해 줘.
```

✅ **확인**
- [ ] Kiro가 `src/todo.js` 를 저장한 직후 `node --test` 가 **자동으로** 실행되었다. (Hook 실행 표시 또는 출력)
- [ ] 결과가 `# fail 0` 이다.
- [ ] 자동으로 실행되지 않으면 Kiro 패널 › **Agent Hooks** 에서 Hook이 켜져 있는지, 파일 패턴이 `src/…` 를 포함하는지 확인한다.

## 3단계: 앱 실행

🖥️ **터미널**

```bash
python3 -m http.server 8000
```

`Serving HTTP on :: port 8000 …` 이 보이면 서버가 켜진 것이다. 이 터미널은 **그대로 둔다.** (다른 명령은 새 터미널에서)

🌐 **브라우저** — 주소창에 입력

```
http://localhost:8000
```

> ⚠️ `index.html` 을 Finder에서 더블클릭해서 열면(`file://…`) 화면이 비어 보인다. ES 모듈은 반드시 서버 주소로 열어야 한다.

앱 사용을 마치면 서버 터미널에서 `Ctrl + C` 로 끈다.

## 4단계: 화면 둘러보기

처음 열면 할 일이 하나도 없는 빈 목록이 보인다. 화면에는 다음 요소가 있어야 한다. (배치와 문구는 Kiro가 만든 디자인에 따라 다르다)

```
┌──────────────────────────────────────────┐
│  할 일 목록                                │
│  ┌──────────────────────────┐ ┌──────┐   │
│  │ 할 일을 입력하세요          │ │ 추가 │   │  ← ① 입력란 + 추가 버튼
│  └──────────────────────────┘ └──────┘   │
│  (안내 문구 자리)                           │  ← ② 안내 문구
│  [전체] [진행 중] [완료]   남은 할 일 0개     │  ← ③ 필터 · ④ 남은 개수
│                                          │
│  ☐ (할 일 목록이 여기에 표시)       [삭제]  │  ← ⑤ 체크 상자 · 내용 · 삭제 버튼
└──────────────────────────────────────────┘
```

| 번호 | 요소 | 하는 일 |
| --- | --- | --- |
| ① | 입력란 + 추가 버튼 | 새 할 일 입력. **Enter** 로도 추가 |
| ② | 안내 문구 | 빈 입력, 200자 초과, 중복 등을 알려 줌 |
| ③ | 필터 | 전체 / 진행 중 / 완료 목록 보기 |
| ④ | 남은 할 일 | 완료하지 않은 할 일 수. **필터와 상관없이 전체 기준** |
| ⑤ | 할 일 항목 | 체크 상자(완료) · 내용 · 삭제 버튼 |

✅ **확인**
- [ ] ①~⑤ 요소가 모두 보인다.
- [ ] 남은 할 일이 `0` 으로 표시된다.
- [ ] 이미 할 일이 보이면 예전에 같은 주소로 쓰던 데이터다. 6단계의 **데이터 초기화**를 먼저 한다.

## 5단계: 기능별로 써 보고 확인하기

아래 시나리오를 **위에서부터 순서대로** 해 본다. 앞 시나리오의 결과가 다음 시나리오의 시작 상태다. 각 묶음은 `requirements.md` 의 요구사항과 대응한다. (요구사항 번호는 Kiro가 정한 순서에 따라 다를 수 있다)

### 5-1. 할 일 추가

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| A1 | `우유 사기` 입력 → **Enter** | 목록 끝에 미완료로 추가, 입력란 비워짐, 남은 할 일 `1` |
| A2 | `책 반납하기` 입력 → **추가** 버튼 | 목록 끝에 추가, 남은 할 일 `2` |
| A3 | `운동하기` 도 추가 | 추가한 순서대로 3개, 남은 할 일 `3` |
| A4 | 아무것도 입력하지 않고 **Enter** | 추가되지 않고 안내 문구 표시 |
| A5 | 스페이스만 여러 번 입력하고 **Enter** | 추가되지 않고 안내 문구 표시 |
| A6 | `우유 사기` 를 한 번 더 추가 | 두 번째 `우유 사기` 도 추가되고 **중복 안내** 문구, 남은 할 일 `4` |
| A7 | 201자 이상 붙여 넣고 **Enter** (아래 💡) | 추가되지 않고 글자 수 초과 안내 |

> 💡 201자 텍스트 만들기: 🖥️ 새 터미널에서 `python3 -c "print('가'*201)" | pbcopy` → 입력란에 **⌘ + V**

A6 에서 추가한 두 번째 `우유 사기` 는 삭제 버튼으로 지운다. → 목록: `우유 사기`, `책 반납하기`, `운동하기` (남은 할 일 3개)

### 5-2. 완료 체크와 해제

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| C1 | `우유 사기` 체크 상자 클릭 | 완료 표시(취소선 등), 남은 할 일 `2` |
| C2 | 같은 체크 상자 다시 클릭 | 미완료로 돌아감, 남은 할 일 `3` |
| C3 | `우유 사기` 다시 체크 | 완료, 남은 할 일 `2` (이 상태 유지) |

### 5-3. 필터

현재 상태: `우유 사기`(완료), `책 반납하기`, `운동하기`(미완료)

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| F1 | **진행 중** 선택 | `책 반납하기`, `운동하기` 만 보임, 남은 할 일 `2` (그대로) |
| F2 | **완료** 선택 | `우유 사기` 만 보임, 남은 할 일 `2` (그대로) |
| F3 | **전체** 선택 | 3개 모두 보임 |
| F4 | **진행 중** 선택 후 `운동하기` 체크 | `운동하기` 가 목록에서 사라짐, 남은 할 일 `1` |
| F5 | **전체** 로 돌아가 `운동하기` 체크 해제 | 남은 할 일 `2` |

### 5-4. 삭제

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| D1 | `책 반납하기` 의 **삭제** | **확인 창 없이** 즉시 사라짐, 남은 할 일 `1` |
| D2 | 완료된 `우유 사기` 삭제 | 사라짐, 남은 할 일은 그대로 `1` |

### 5-5. 데이터 유지 (새로 고침 · 브라우저 재시작)

`운동하기`(미완료) 하나만 남은 상태에서 `빨래하기` 를 추가하고 체크해 둔다. (남은 할 일 1개)

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| P1 | 새로 고침 (**⌘ + R**) | `운동하기`(미완료), `빨래하기`(완료) 가 그대로, 남은 할 일 `1` |
| P2 | 탭을 닫고 새 탭에서 `http://localhost:8000` | 그대로 |
| P3 | 브라우저를 완전히 종료(**⌘ + Q**) 후 다시 열어 접속 | 그대로 |
| P4 | 서버를 `Ctrl + C` 로 껐다가 다시 켜고 접속 | 그대로 (데이터는 서버가 아니라 **브라우저**에 저장되기 때문) |

> 💡 시크릿(비공개) 창은 창을 닫으면 데이터가 지워지는 것이 정상이다. 확인은 일반 창에서 한다.

### 5-6. 키보드만으로 사용하기

마우스에서 손을 떼고 진행한다.

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| K1 | **Tab** 을 여러 번 | 입력란 → 추가 → 필터 → 체크 상자 → 삭제 버튼으로 이동, **초점 테두리가 항상 보임** |
| K2 | 입력란에서 `키보드 테스트` 입력 → **Enter** | 추가됨 |
| K3 | 체크 상자에서 **Space** | 완료/해제 |
| K4 | 삭제 버튼에서 **Enter** | 삭제됨 |
| K5 | 필터에서 **Enter** 또는 방향키 | 필터가 바뀜 |
| K6 | **Shift + Tab** | 반대 방향으로 이동 |

✅ **5단계 종합 확인**
- [ ] 5-1 ~ 5-6 의 모든 시나리오가 "이렇게 되어야 한다"와 같다.
- [ ] 화면에 영어 문구가 없다. (스티어링: 화면 문구는 한국어)
- [ ] 다르게 동작한 시나리오 번호를 메모했다 → 7단계에서 처리한다.

## 6단계: 저장된 데이터 직접 들여다보기

앱이 데이터를 **브라우저 안(localStorage)에만** 저장하는지 눈으로 확인한다. (스티어링 `tech.md`: 외부로 데이터를 보내지 않는다)

어떤 키 이름을 쓰는지 먼저 코드에서 확인한다.

🖥️ **터미널**

```bash
grep -n "localStorage\|KEY" src/storage.js
```

🌐 **브라우저 (Chrome 기준)**

1. 앱 화면에서 **⌘ + ⌥ + I** (개발자 도구)
2. **Application** 탭 → 왼쪽 **Storage › Local storage › http://localhost:8000**
3. 위에서 확인한 키와 JSON 값이 보인다. (예시)

```json
[{"id":3,"text":"운동하기","completed":false},{"id":5,"text":"빨래하기","completed":true}]
```

> Safari: 설정 › 고급 › "웹 개발자용 기능 보기" 켜기 → **⌥ + ⌘ + I** → **저장 공간** 탭

**외부 전송 확인** — **Network** 탭을 열고 새로 고침한 뒤 할 일을 추가·체크·삭제해 본다.

**저장 데이터 손상 확인** — **Console** 탭에서 (`<키>` 는 위에서 확인한 이름)

```js
localStorage.setItem('<키>', 'abc'); location.reload();
```

**데이터 초기화** — **Console** 탭에서

```js
localStorage.clear(); location.reload();
```

✅ **확인**
- [ ] 화면의 할 일과 localStorage 의 JSON 내용이 일치한다.
- [ ] Network 탭에 `localhost` 밖으로 나가는 요청이 없다.
- [ ] 손상 데이터를 넣어도 앱이 멈추지 않고 빈 목록으로 시작한다. (GUIDE 4단계에서 설계에 넣은 오류 처리)
- [ ] 초기화 후 빈 목록, 남은 할 일 `0` 으로 돌아간다.

## 7단계: 요구사항과 다를 때 고치기

5·6단계에서 다르게 동작한 것이 있으면, **무엇이 기준인지 먼저 판단**한다.

| 상황 | 기준 | 할 일 |
| --- | --- | --- |
| 요구사항은 맞는데 앱이 다르게 동작 | **requirements.md** | 코드 수정 요청 |
| 앱 동작이 오히려 맞거나, 새로 정할 것이 생김 | **새 결정** | 요구사항 → 설계 수정 → **Sync Files** → 작업 실행 ([GUIDE.md 8단계](GUIDE.md#8-단계-도전-기존-spec에-마감일-기능-추가)와 같은 방법) |

👻 **Kiro 채팅** — 코드가 요구사항과 다를 때

```text
#spec:todo-list 앱을 직접 확인해 보니 아래 동작이 요구사항과 달라. 요구사항에 맞게 코드를 고치고, 이 경우를 잡아내는 테스트도 추가해 줘.
- 시나리오 F4: 진행 중 필터에서 할 일을 체크해도 목록에서 사라지지 않음
```

👻 **Kiro 채팅** — 요구사항을 바꿔야 할 때 (예: 완료된 할 일을 맨 아래로)

```text
#spec:todo-list 완료한 할 일은 목록 맨 아래로 내려가도록 요구사항을 추가하고, design.md 도 맞춰 줘.
```

그다음 `tasks.md` 에서 **Sync Files** → 새 작업 실행 → 이 문서 2단계(테스트)와 5단계(직접 확인)를 다시 한다.

✅ **확인**
- [ ] 수정 후 `node --test` 가 `# fail 0` 이다.
- [ ] 문제였던 시나리오를 다시 해 보니 기대대로 동작한다.
- [ ] `tasks.md` 의 작업이 모두 완료로 표시되어 있다.

## 8단계: (도전) 마감일 기능 써 보기

[GUIDE.md 8단계](GUIDE.md#8-단계-도전-기존-spec에-마감일-기능-추가)에서 같은 Spec에 마감일 기능을 추가했다면 아래를 확인한다. 서버를 다시 켜고 **⌘ + Shift + R** (강력 새로 고침)로 연다.

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| U1 | 기존에 있던 `운동하기` 확인 | 마감일 없이 그대로 보임 (기존 데이터 호환) |
| U2 | `보고서 제출` 입력, 마감일을 **내일**로 선택 후 추가 | 할 일 옆에 마감일 표시 |
| U3 | `세금 납부` 입력, 마감일을 **어제**로 선택 후 추가 | 지난 마감으로 **눈에 띄게 표시** |
| U4 | `세금 납부` 체크 | 완료되면 지난 마감 강조가 사라지거나 약해짐 (요구사항에 따라) |
| U5 | 마감일 없이 `물 마시기` 추가 | 정상 추가 |
| U6 | **마감일 순 정렬** 선택 | `세금 납부`(어제) → `보고서 제출`(내일) 순, 마감일 없는 항목은 요구사항에 정한 위치 |
| U7 | 새로 고침 | 마감일이 유지됨 |

✅ **확인**
- [ ] U1~U7 이 모두 기대대로 동작한다.
- [ ] 6단계 방법으로 보면 마감일이 `YYYY-MM-DD` 형식으로 저장되어 있다.
- [ ] 5단계 시나리오도 다시 해 보니 그대로 동작한다. (기존 기능이 깨지지 않음)
- [ ] `node --test` 가 `# fail 0` 이다.

## 문제 해결

| 증상 | 해결 |
| --- | --- |
| 화면이 비어 있다 | `file://` 로 열었는지 확인. `python3 -m http.server 8000` 실행 후 `http://localhost:8000` 으로 접속 |
| `Address already in use` | 8000 포트를 다른 프로그램이 사용 중. `python3 -m http.server 8080` 으로 바꾸고 `http://localhost:8080` 접속 |
| 코드를 고쳤는데 화면이 그대로다 | 브라우저 캐시. **⌘ + Shift + R** (강력 새로 고침) |
| 새로 고침하면 데이터가 사라진다 | 시크릿 창이 아닌지 확인. 일반 창에서도 사라지면 시나리오 번호(P1 등)와 함께 Kiro 채팅에 수정 요청 |
| `node --test` 에서 `Cannot use import statement` | `package.json` 에 `"type": "module"` 이 있는지 확인. 없으면 Kiro에 추가 요청 |
| `node --test` 가 테스트를 하나도 못 찾는다 | 테스트 파일 이름이 `*.test.js` 이고 `tests/` 폴더에 있는지 확인 |
| `node: command not found` | Node.js 설치 후 Kiro를 다시 시작 (Kiro 터미널이 새 PATH를 읽도록) |
| 파일을 저장해도 Hook이 안 돈다 | 파일 이벤트 Hook은 **에이전트가 저장한 파일**에 반응한다. 직접 편집기에서 저장한 경우는 해당하지 않을 수 있다 |
| 개발자 도구 Console 에 빨간 오류가 있다 | 오류 메시지를 복사해 Kiro 채팅에 "#spec:todo-list 브라우저 콘솔 오류야. 고쳐 줘" 와 함께 붙여 넣기 |
| 화면 문구·배치가 이 문서 그림과 다르다 | 정상이다. Kiro가 디자인을 정하므로 **기능(5단계 시나리오)이 같으면** 통과 |
