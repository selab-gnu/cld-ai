# 설계 결정 기록 (ADR)

## 파일

- 위치: `docs/adr/NNNN-짧은-제목.md` (예: `docs/adr/0001-json-file-storage.md`)
- 번호는 0001부터 차례로 붙이고 다시 쓰지 않는다.
- `docs/adr/README.md`에 전체 ADR 목록 표(번호, 제목, 상태)를 유지한다.

## 양식

```markdown
# ADR-0001: 결정을 한 문장으로

## 상태
제안 | 승인 | 대체됨 (ADR-000N)

날짜: YYYY-MM-DD

## 배경
어떤 문제나 제약 때문에 결정이 필요했는지. 관련 요구사항 ID(REQ-xxx)가 있으면 적는다.

## 고려한 대안
| 대안 | 장점 | 단점 |
|---|---|---|

## 결정
무엇을 하기로 했는지 한두 문장.

## 결과
이 결정으로 좋아지는 점, 감수하는 점, 나중에 다시 검토할 조건.
```

`## 상태`, `## 배경`, `## 결정`, `## 결과` 네 섹션은 반드시 있어야 한다(`scripts/check-docs.mjs`가 검사한다).

## 절차

1. 결정의 **이유**는 코드에 남지 않는다. 배경과 대안은 사람에게 물어서 채우고, 모르는 부분은 "확인 필요"로 표시한다. 추측으로 채우지 않는다.
2. 에이전트가 쓴 ADR은 상태를 `제안`으로 둔다. 사람이 확인하면 `승인`으로 바꾼다.
3. `승인`된 ADR의 본문은 고치지 않는다. 결정을 바꾸려면 새 ADR을 쓰고, 옛 ADR의 상태만 `대체됨 (ADR-000N)`으로 바꾼다.
4. 관련 문서(아키텍처 그림, 요구사항)에서 해당 ADR로 링크한다.
