# 설계 모델링 (C4 + Mermaid)

## 파일

`docs/architecture/overview.md` 한 파일에 아래 순서로 둔다. 그림은 모두 Mermaid 코드 블록으로 쓴다(GitHub와 대부분의 편집기에서 바로 그림으로 보인다).

1. **시스템 컨텍스트** — 사용자와 외부 시스템 사이에서 이 시스템이 어디에 있는지
2. **컨테이너** — 실행 단위(CLI, HTTP 서버)와 데이터 저장소(JSON 파일)
3. **컴포넌트** — 소스 파일(모듈) 사이의 의존 방향
4. **동적 뷰** — 대표 요청 하나의 처리 순서 (`sequenceDiagram`)
5. **관련 결정** — 그림에 반영된 ADR 링크

## 작성 규칙

- C4 수준마다 그림을 따로 그리고, 한 그림의 요소는 10개 이하로 유지한다.
- 그림은 `flowchart`로 그리고, 노드 이름에 종류를 함께 적는다. 예: `cli["CLI<br/>(Node.js, src/cli.js)"]`
- 화살표에는 무엇을 주고받는지 적는다. 예: `cli -->|"읽기/쓰기"| store`
- 각 그림 아래에 2~3줄 설명과 **근거 파일 경로**를 적는다.
- 그림 맨 위에 "이 문서는 코드에서 생성했으며 YYYY-MM-DD 기준"이라고 적는다.
- 코드에서 확인할 수 없는 것(배포 환경, 향후 계획)은 그리지 않는다.
- 설계 **이유**는 그림에 쓰지 않고 ADR로 링크한다.

## 절차

1. `src/`의 import 관계와 진입점(`src/cli.js`, `src/server.js`)을 읽는다.
2. 위 순서로 그림을 그린다.
3. 코드가 바뀐 뒤 갱신할 때는 바뀐 부분만 고치고 기준 날짜를 바꾼다.
