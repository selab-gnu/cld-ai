# 요구사항 목록 관리

## 파일과 형식

요구사항은 `docs/requirements.md` 한 파일에 표로 관리한다. 표의 열 순서는 바꾸지 않는다(`scripts/check-docs.mjs`가 이 순서로 읽는다).

```markdown
| ID | 요구사항 | 우선순위 | 상태 | 검증 |
|---|---|---|---|---|
| REQ-001 | 사용자가 제목을 입력하면, 시스템은 새 할 일을 미완료 상태로 추가해야 한다. | 필수 | 구현됨 | `test/todo.test.js` |
```

- **ID**: `REQ-` + 세 자리 숫자. 한 번 쓴 번호는 지워진 요구사항이라도 다시 쓰지 않는다.
- **요구사항**: 아래 EARS 문형 중 하나로, 한 행에 한 가지 동작만 적는다.
- **우선순위**: `필수` / `권장` / `선택`
- **상태**: `제안`(에이전트가 추정, 사람 확인 전) → `승인`(구현 예정) → `구현됨`(테스트로 검증됨). 폐기하면 `폐기`.
- **검증**: 이 요구사항을 검증하는 테스트 파일. 테스트 이름 앞에는 `[REQ-001]`처럼 ID를 붙인다.

표 위에는 "범위"(이 문서가 다루는 것과 다루지 않는 것)를, 표 아래에는 "용어" 표를 둔다.

## EARS 문형

| 종류 | 문형 |
|---|---|
| 항상 | 시스템은 ~해야 한다. |
| 이벤트 | 사용자가 ~하면, 시스템은 ~해야 한다. |
| 상태 | ~인 동안, 시스템은 ~해야 한다. |
| 예외 | 만약 ~이면, 시스템은 ~해야 한다. |
| 선택 기능 | ~ 기능이 있는 경우, 시스템은 ~해야 한다. |

오류 처리는 "예외" 문형으로 별도 행을 만든다. 예: "만약 제목이 비어 있으면, 시스템은 할 일을 추가하지 않고 오류를 알려야 한다."

## 절차

**코드에서 추출할 때**
1. `src/`와 `test/`를 읽고, 사용자가 관찰할 수 있는 동작만 요구사항으로 적는다(내부 구현 방식은 적지 않는다).
2. 모든 행의 상태를 `제안`으로 둔다. 테스트로 확인되지 않는 동작은 "검증" 칸을 비워 둔다.
3. 사람에게 목록을 보여 주고 확인을 받는다. 확인받은 행만 `구현됨`(테스트가 있으면) 또는 `승인`으로 바꾼다.
4. `구현됨`으로 바꾼 행의 테스트 이름 앞에 `[REQ-xxx]`를 붙인다.

**새 기능을 추가할 때**
1. 마지막 번호 다음 ID로 행을 추가하고 상태를 `승인`으로 둔다.
2. 구현과 테스트가 끝나면 `구현됨`으로 바꾸고 테스트 이름에 ID를 붙인다.

마지막에 `npm run docs:check`를 실행해 [1] 요구사항 추적에 오류가 없는지 확인한다.
