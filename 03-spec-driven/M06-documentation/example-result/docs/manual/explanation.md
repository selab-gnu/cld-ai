# 동작 원리

## 번호는 어떻게 매겨지나요?

새 할 일의 번호는 **지금 있는 번호 중 가장 큰 값 + 1**입니다. 목록이 비어 있으면 1번부터 시작합니다. 그래서 번호는 항상 1 이상이고 목록 안에서 서로 겹치지 않습니다(요구사항 REQ-002).

삭제하면 할 일이 목록에서 완전히 사라지므로, **가장 큰 번호를 지운 뒤 새로 추가하면 그 번호가 다시 쓰입니다.** 예를 들어 1, 2번이 있을 때 2번을 지우고 추가하면 새 할 일은 다시 2번입니다. 이렇게 정한 이유는 [ADR-0002](../adr/0002-hard-delete.md)에 있습니다.

## 데이터는 어디에 저장되나요?

할 일 목록 전체가 JSON 파일 하나(기본 `todos.json`)에 저장되고, 추가하거나 완료할 때마다 파일 전체를 다시 씁니다. 파일을 열어 내용을 직접 볼 수 있습니다.

```json
[
  { "id": 1, "title": "우유 사기", "done": true }
]
```

이 방식을 고른 이유와 한계는 [ADR-0001](../adr/0001-json-file-storage.md)에 있습니다.

## CLI와 서버를 동시에 써도 되나요?

둘은 같은 저장 파일을 쓸 수 있지만, **동시에 변경하면 나중에 쓴 쪽의 내용만 남을 수 있습니다.** 한 번에 한 쪽만 쓰거나, `TODO_FILE`로 서로 다른 파일을 쓰세요.
