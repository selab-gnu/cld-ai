# 예제 실행 및 확인 — 할 일 관리 앱 사용 가이드

> 이 문서는 OpenSpec으로 **완성한 할 일 관리 앱을 실행하고, 직접 써 보고, 명세대로 동작하는지 확인하는 방법**을 안내한다.
> 앱을 만드는 과정(설치 → propose → apply → archive)은 [GUIDE.md](GUIDE.md) 를 따른다.

**시작 조건**: [GUIDE.md](GUIDE.md) 6단계(`/opsx:apply add-todo-list`)까지 마쳐서 `my-todo-openspec` 폴더에 앱 코드가 생긴 상태

| 표시 | 하는 곳 |
| --- | --- |
| 🖥️ **터미널** | macOS 터미널 (`my-todo-openspec` 폴더 안) |
| 🌐 **브라우저** | Chrome / Safari 등 |
| 🤖 **Claude Code** | 문제가 있을 때 수정 요청 |

---

## 1단계: 실행 전 파일 확인

🖥️ **터미널**

```bash
cd ~/git/my-todo-openspec      # 프로젝트를 만든 위치로 이동
ls
ls src tests
```

✅ **확인** — 아래 파일이 있으면 실행할 준비가 된 것이다. (파일 이름은 AI가 조금 다르게 만들 수 있다)

```
index.html   package.json   styles.css   src/   tests/   openspec/
src:   app.js   storage.js   todo.js
tests: todo.test.js
```

| 파일 | 역할 |
| --- | --- |
| `index.html` | 앱 화면 (브라우저로 여는 파일) |
| `src/todo.js` | 할 일 추가·완료·삭제·필터 같은 **핵심 로직** (테스트 대상) |
| `src/storage.js` | 브라우저 localStorage 저장·불러오기 |
| `src/app.js` | 화면 그리기와 버튼·키보드 이벤트 처리 |
| `tests/todo.test.js` | 핵심 로직 자동 테스트 |

## 2단계: 자동 테스트 실행

🖥️ **터미널**

```bash
node --test
```

✅ **기대 출력** (마지막 부분)

```
# tests 12        ← 테스트 개수는 AI가 만든 만큼 (예시)
# pass 12
# fail 0
```

- `# fail 0` 이면 핵심 로직이 정상이다.
- 실패가 있으면 출력 전체를 복사해 Claude Code에 붙여 넣는다.

🤖 **Claude Code**

```text
node --test 결과가 아래와 같아. openspec/changes/add-todo-list/specs/todo-list/spec.md 명세 기준으로 원인을 찾아 고쳐 줘.
(테스트 출력 붙여 넣기)
```

## 3단계: 앱 실행

🖥️ **터미널**

```bash
python3 -m http.server 8000
```

`Serving HTTP on :: port 8000 …` 이 보이면 서버가 켜진 것이다. 이 터미널은 **그대로 둔다.**

🌐 **브라우저** — 주소창에 입력

```
http://localhost:8000
```

> ⚠️ `index.html` 을 Finder에서 더블클릭해서 열면(`file://…`) 화면이 비어 보인다. ES 모듈은 반드시 서버 주소로 열어야 한다.

앱 사용을 마치면 서버 터미널에서 `Ctrl + C` 로 끈다.

## 4단계: 화면 둘러보기

처음 열면 할 일이 하나도 없는 빈 목록이 보인다. 화면에는 다음 요소가 있어야 한다. (배치와 문구는 AI가 만든 디자인에 따라 다르다)

```
┌──────────────────────────────────────────┐
│  할 일                                    │
│  ┌──────────────────────────┐ ┌──────┐   │
│  │ 할 일을 입력하세요          │ │ 추가 │   │  ← ① 입력창 + 추가 버튼
│  └──────────────────────────┘ └──────┘   │
│                                          │
│  ☐ (할 일 목록이 여기에 표시)       [삭제]  │  ← ② 체크박스 · 텍스트 · 삭제 버튼
│                                          │
│  남은 할 일: 0개   [전체] [진행 중] [완료]   │  ← ③ 남은 개수 · ④ 필터
└──────────────────────────────────────────┘
```

| 번호 | 요소 | 하는 일 |
| --- | --- | --- |
| ① | 입력창 + 추가 버튼 | 새 할 일 입력. Enter 키로도 추가 |
| ② | 체크박스 / 삭제 버튼 | 완료 표시·해제 / 할 일 삭제 |
| ③ | 남은 할 일 개수 | 완료되지 않은 할 일 수 |
| ④ | 필터 버튼 | 전체 / 진행 중 / 완료 목록 보기 |

✅ **확인**
- [ ] ①~④ 요소가 모두 보인다.
- [ ] 남은 할 일이 `0` 으로 표시된다.

## 5단계: 기능별로 써 보고 확인하기

아래 시나리오를 **위에서부터 순서대로** 해 본다. 각 시나리오는 명세(`spec.md`)의 `#### Scenario` 와 대응한다.

### 5-1. 할 일 추가

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| A1 | 입력창에 `우유 사기` 입력 → **Enter** | 목록에 `우유 사기` 가 미완료로 추가, 입력창은 비워짐, 남은 할 일 `1` |
| A2 | `책 반납하기` 입력 → **추가 버튼** 클릭 | 목록 끝에 추가, 남은 할 일 `2` |
| A3 | `운동하기` 도 추가 | 추가한 순서대로 3개가 보임, 남은 할 일 `3` |
| A4 | 아무것도 입력하지 않고 Enter | 아무것도 추가되지 않음 |
| A5 | 스페이스만 여러 번 입력하고 Enter | 아무것도 추가되지 않음 (안내 문구가 나올 수 있음) |
| A6 | (GUIDE 5단계에서 200자 제한을 넣었다면) 201자 이상 입력 | 추가되지 않거나 200자에서 더 입력되지 않음 |

> 💡 A6용 긴 텍스트 만들기: 🖥️ 새 터미널 탭에서 `python3 -c "print('가'*201)" | pbcopy` 실행 후 입력창에 붙여 넣기(⌘V)

### 5-2. 완료 체크와 해제

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| C1 | `우유 사기` 체크박스 클릭 | 완료 표시(취소선 등), 남은 할 일 `2` |
| C2 | 같은 체크박스 다시 클릭 | 미완료로 돌아감, 남은 할 일 `3` |
| C3 | `우유 사기` 다시 체크 | 완료, 남은 할 일 `2` (다음 시나리오를 위해 이 상태 유지) |

### 5-3. 필터

현재 상태: `우유 사기`(완료), `책 반납하기`, `운동하기`(미완료)

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| F1 | **진행 중** 클릭 | `책 반납하기`, `운동하기` 만 보임 |
| F2 | **완료** 클릭 | `우유 사기` 만 보임 |
| F3 | **전체** 클릭 | 3개 모두 보임 |
| F4 | **진행 중** 필터 상태에서 `운동하기` 체크 | `운동하기` 가 목록에서 사라짐(완료로 이동), 남은 할 일 `1` |
| F5 | **전체** 로 돌아가 `운동하기` 체크 해제 | 남은 할 일 `2` |

✅ 필터와 상관없이 **남은 할 일 개수는 항상 전체 기준**으로 표시되어야 한다.

### 5-4. 삭제

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| D1 | `책 반납하기` 의 삭제 버튼 클릭 | 목록에서 사라짐, 남은 할 일 `1` |
| D2 | (GUIDE 5단계에서 "확인 창 없이 삭제"로 정했다면) | 확인 창 없이 즉시 삭제됨 |
| D3 | 완료된 `우유 사기` 삭제 | 사라짐, 남은 할 일은 그대로 `1` |

### 5-5. 데이터 유지 (새로 고침 · 브라우저 재시작)

먼저 `운동하기`(미완료) 하나만 남은 상태에서 `빨래하기` 를 추가하고 체크해 둔다.

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| P1 | 새로 고침 (**⌘ + R**) | `운동하기`(미완료), `빨래하기`(완료) 가 그대로, 남은 할 일 `1` |
| P2 | 탭을 닫고 새 탭에서 `http://localhost:8000` | 같은 상태 그대로 |
| P3 | 브라우저를 완전히 종료(**⌘ + Q**) 후 다시 열어 접속 | 같은 상태 그대로 |
| P4 | 서버를 `Ctrl + C` 로 껐다가 다시 `python3 -m http.server 8000` | 같은 상태 그대로 (데이터는 서버가 아니라 브라우저에 저장되기 때문) |

> 💡 시크릿(비공개) 창에서는 창을 닫으면 데이터가 지워지는 것이 정상이다. 확인은 일반 창에서 한다.

### 5-6. 키보드만으로 사용하기

마우스에서 손을 떼고 진행한다.

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| K1 | 주소창 클릭 후 **Tab** 을 여러 번 | 입력창 → 추가 버튼 → 체크박스 → 삭제 버튼 → 필터 순으로 포커스(테두리)가 이동 |
| K2 | 입력창에서 `키보드 테스트` 입력 → **Enter** | 추가됨 |
| K3 | 체크박스에 포커스 → **Space** | 완료/해제가 바뀜 |
| K4 | 삭제 버튼에 포커스 → **Enter** | 삭제됨 |
| K5 | 필터 버튼에 포커스 → **Enter** | 필터가 바뀜 |
| K6 | **Shift + Tab** | 포커스가 반대 방향으로 이동 |

✅ **5단계 종합 확인**
- [ ] 5-1 ~ 5-6 의 모든 시나리오가 "이렇게 되어야 한다"와 같다.
- [ ] 다르게 동작한 시나리오 번호를 메모했다 → 7단계에서 처리한다.

## 6단계: 저장된 데이터 직접 들여다보기

앱이 데이터를 **브라우저 안(localStorage)에만** 저장하는지 눈으로 확인한다.

🌐 **브라우저 (Chrome 기준)**

1. 앱 화면에서 **⌘ + ⌥ + I** (개발자 도구 열기)
2. 상단 탭 **Application** → 왼쪽 **Storage › Local storage › http://localhost:8000**
3. 오른쪽에 키 하나와 JSON 값이 보인다. 예:

```json
[{"id":"…","text":"운동하기","completed":false,"createdAt":"…"},
 {"id":"…","text":"빨래하기","completed":true,"createdAt":"…"}]
```

> Safari는 설정 › 고급 › "웹 개발자용 기능 보기"를 켠 뒤 **⌥ + ⌘ + I** → **저장 공간** 탭에서 볼 수 있다.

어떤 키 이름을 쓰는지는 코드에서 확인할 수 있다.

🖥️ **터미널**

```bash
grep -n "localStorage" src/storage.js
```

**데이터 초기화(처음 상태로)** — 개발자 도구의 **Console** 탭에서

```js
localStorage.clear(); location.reload();
```

✅ **확인**
- [ ] 화면의 할 일과 localStorage 의 JSON 내용이 일치한다.
- [ ] 개발자 도구 **Network** 탭에 할 일을 추가할 때 외부 서버로 가는 요청이 없다. (원칙: 외부 전송 금지)
- [ ] 초기화 후 빈 목록, 남은 할 일 `0` 으로 돌아간다.

## 7단계: 명세와 다를 때 고치기

5단계에서 다르게 동작한 시나리오가 있으면, **무엇이 기준인지 먼저 판단**한다.

| 상황 | 기준 | 할 일 |
| --- | --- | --- |
| 명세는 맞는데 앱이 다르게 동작 | **명세** | 코드 수정을 요청 |
| 앱 동작이 오히려 맞고 명세가 틀림 / 새로 정할 것이 생김 | **새 결정** | 명세부터 수정 → 다시 구현 ([GUIDE.md 5단계](GUIDE.md#5-단계-검토와-수정-review--update) `/opsx:update`) |

🤖 **Claude Code** — 코드가 명세와 다를 때

```text
앱을 직접 확인해 보니 아래 동작이 명세(openspec/changes/add-todo-list/specs/todo-list/spec.md)와 달라. 명세에 맞게 코드를 고치고, 이 경우를 잡아내는 테스트도 추가해 줘.
- 시나리오 F4: 진행 중 필터에서 할 일을 체크해도 목록에서 사라지지 않음
```

🤖 **Claude Code** — 명세를 바꿔야 할 때

```text
/opsx:update add-todo-list - 완료된 할 일은 목록 맨 아래로 내려가도록 바꾸고 싶어. 명세 시나리오와 작업을 맞춰 줘.
```

그다음 `/opsx:apply add-todo-list` 로 구현하고, 이 문서 2단계(테스트)와 5단계(직접 확인)를 다시 한다.

✅ **확인**
- [ ] 수정 후 `node --test` 가 `# fail 0` 이다.
- [ ] 문제였던 시나리오를 다시 해 보니 기대대로 동작한다.
- [ ] 모든 시나리오가 통과하면 GUIDE.md 7단계(`/opsx:archive`)로 넘어간다.

## 8단계: (도전) 마감일 기능 써 보기

[GUIDE.md 8단계](GUIDE.md#8-단계-도전-두-번째-변경--기존-명세-수정하기)에서 두 번째 변경 `add-due-date` 를 구현했다면 아래를 확인한다. 서버를 다시 켜고 **⌘ + Shift + R** (강력 새로 고침)로 연다.

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| U1 | 기존에 있던 `운동하기` 확인 | 마감일 없이 그대로 보임 (기존 데이터 호환) |
| U2 | `보고서 제출` 입력, 마감일을 **내일**로 선택 후 추가 | 할 일 옆에 마감일 표시 |
| U3 | `세금 납부` 입력, 마감일을 **어제**로 선택 후 추가 | 지난 마감으로 **눈에 띄게 표시**(빨간색 등) |
| U4 | `세금 납부` 체크 | 완료되면 지난 마감 강조가 사라지거나 약해짐 (명세에 따라) |
| U5 | 마감일 없이 `물 마시기` 추가 | 마감일 없이 정상 추가 |
| U6 | **마감일 순 정렬** 선택 | `세금 납부`(어제) → `보고서 제출`(내일) 순, 마감일 없는 항목은 명세에 정한 위치(보통 맨 아래) |
| U7 | 새로 고침 | 마감일과 정렬 상태가 명세대로 유지 |

✅ **확인**
- [ ] U1~U7 이 모두 기대대로 동작한다.
- [ ] 6단계 방법으로 localStorage 를 보면 마감일이 `YYYY-MM-DD` 형식으로 저장되어 있다.
- [ ] `node --test` 가 `# fail 0` 이다.

## 문제 해결

| 증상 | 해결 |
| --- | --- |
| 화면이 비어 있다 | `file://` 로 열었는지 확인. `python3 -m http.server 8000` 실행 후 `http://localhost:8000` 으로 접속 |
| `Address already in use` | 8000 포트를 다른 프로그램이 사용 중. `python3 -m http.server 8080` 으로 바꾸고 `http://localhost:8080` 접속 |
| 코드를 고쳤는데 화면이 그대로다 | 브라우저 캐시. **⌘ + Shift + R** (강력 새로 고침) |
| 새로 고침하면 데이터가 사라진다 | 시크릿 창이 아닌지 확인. 일반 창에서도 사라지면 5-5 시나리오 번호와 함께 Claude Code에 수정 요청 |
| `node --test` 에서 `Cannot use import statement` 오류 | `package.json` 에 `"type": "module"` 이 있는지 확인. 없으면 Claude Code에 추가 요청 |
| `node --test` 가 테스트를 하나도 못 찾는다 | 테스트 파일 이름이 `*.test.js` 이고 `tests/` 폴더에 있는지 확인 |
