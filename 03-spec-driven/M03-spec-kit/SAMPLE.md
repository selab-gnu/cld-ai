# 예제 실행 및 확인 — 할 일 관리 앱(my-todo) 사용 가이드

> 이 문서는 Spec Kit으로 **완성한 할 일 관리 앱을 실행하고, 직접 써 보고, 명세대로 동작하는지 확인하는 방법**을 안내한다.
> 앱을 만드는 과정(설치 → constitution → specify → … → implement → converge)은 [GUIDE.md](GUIDE.md) 를 따른다.

**시작 조건**: [GUIDE.md](GUIDE.md) 7단계(`/speckit-implement`)까지 마쳐서 `my-todo` 폴더에 앱 코드가 생긴 상태

| 표시 | 하는 곳 |
| --- | --- |
| 🖥️ **터미널** | macOS 터미널 (`my-todo` 폴더 안) |
| 🌐 **브라우저** | Chrome / Safari 등 |
| 🤖 **Claude Code** | 문제가 있을 때 수정 요청 |

> 💡 [GUIDE-codex.md](GUIDE-codex.md) 로 **Codex** 를 써서 만들었다면, 폴더 이름을 `my-todo-codex` 로 바꿔 읽고, 🤖 **Claude Code** 대신 Codex에서 `/speckit-…` 를 **`$speckit-…`** 로 입력한다. (`/clear` → `/new`)

> 📝 이 문서의 화면 문구·메시지·테스트 개수는 실제로 Spec Kit으로 만든 `my-todo` 앱에서 확인한 값이다. AI가 만드는 코드는 실행할 때마다 조금씩 달라지므로, **문구가 달라도 같은 기능이 동작하면 통과**로 본다.

> 💡 Spec Kit은 plan 단계에서 `specs/001-todo-list-app/quickstart.md` 라는 **검증 시나리오 문서**를 만들어 준다. 이 문서는 그 내용을 초보자가 따라 하기 쉽게 풀어 쓴 것이다. 내 앱의 quickstart.md 도 함께 열어 두고 비교해 보자.

## 1단계: 실행 전 파일 확인

🖥️ **터미널**

```bash
cd ~/git/my-todo      # 프로젝트를 만든 위치로 이동
ls
ls src tests
```

✅ **확인** — 아래와 같은 파일이 있으면 실행할 준비가 된 것이다.

```
index.html   package.json   specs/   src/   tests/
src:   app.js   storage.js   style.css   todo.js
tests: todo.test.js
```

| 파일 | 역할 |
| --- | --- |
| `index.html` | 앱 화면 (브라우저로 여는 파일) |
| `src/todo.js` | 추가·완료·삭제·필터·글자 수 검사 같은 **핵심 로직** (순수 함수, 테스트 대상) |
| `src/storage.js` | 브라우저 localStorage 저장·불러오기 (키: `my-todo:todos`) |
| `src/app.js` | 화면 그리기, 버튼·키보드 이벤트, 안내 문구 |
| `src/style.css` | 화면 꾸미기 (취소선, 초점 테두리, 글자 수 초과 빨간색 등) |
| `tests/todo.test.js` | 핵심 로직 자동 테스트 |
| `package.json` | `{"type": "module"}` 한 줄뿐. 설치할 패키지 없음 (`npm install` 불필요) |

## 3단계: 앱 실행

🖥️ **터미널**

```bash
python3 -m http.server 8000
```

`Serving HTTP on :: port 8000 …` 이 보이면 서버가 켜진 것이다. 이 터미널은 **그대로 둔다.**

🌐 **브라우저** — 주소창에 입력

```
http://localhost:8000
```

> ⚠️ `index.html` 을 Finder에서 더블클릭해서 열면(`file://…`) 앱이 동작하지 않는다. ES 모듈은 반드시 서버 주소로 열어야 한다.

앱 사용을 마치면 서버 터미널에서 `Ctrl + C` 로 끈다.

## 4단계: 화면 둘러보기

처음 열면 아래와 같은 화면이 보인다.

```
┌─────────────────────────────────────────────┐
│  할 일 목록                                   │
│                                             │
│  새 할 일                                     │
│  ┌───────────────────────────────┐ ┌──────┐ │
│  │                               │ │ 추가 │ │  ← ① 입력란 + 추가 버튼
│  └───────────────────────────────┘ └──────┘ │
│  0/200                                      │  ← ② 글자 수
│                                             │  ← ③ 안내 문구 자리
│  ┌ 보기 ───────────────────────────────┐     │
│  │ (●) 전체  ( ) 진행 중  ( ) 완료       │     │  ← ④ 보기(필터) 선택
│  └────────────────────────────────────┘     │
│  남은 할 일 0개                                │  ← ⑤ 남은 개수
│                                             │
│  아직 할 일이 없어요. 첫 할 일을 추가해 보세요.     │  ← ⑥ 목록 (비었을 때 문구)
└─────────────────────────────────────────────┘
```

| 번호 | 요소 | 하는 일 |
| --- | --- | --- |
| ① | 입력란 + 추가 버튼 | 새 할 일 입력. **Enter** 로도 추가 |
| ② | 글자 수 | `입력한 글자 수/200`. 넘으면 `(N자 초과)` 와 함께 빨간색 |
| ③ | 안내 문구 | 빈 입력, 너무 긴 입력, 중복, 저장 실패 등을 알려 줌 |
| ④ | 보기 선택 | 전체 / 진행 중 / 완료 (라디오 버튼, **방향키**로 이동) |
| ⑤ | 남은 할 일 | 완료하지 않은 할 일 수. **보기와 상관없이 전체 기준** |
| ⑥ | 할 일 목록 | 항목마다 체크 상자 · 내용 · 삭제 버튼 |

✅ **확인**
- [ ] `아직 할 일이 없어요. 첫 할 일을 추가해 보세요.`, `남은 할 일 0개`, `0/200` 이 보인다.
- [ ] 이미 할 일이 보인다면 예전에 쓰던 데이터다. 6단계의 **데이터 초기화**를 먼저 한다.

## 5단계: 기능별로 써 보고 확인하기

아래 시나리오를 **위에서부터 순서대로** 해 본다. 앞 시나리오의 결과가 다음 시나리오의 시작 상태다. 각 묶음은 `spec.md` 의 사용자 스토리(User Story)와 대응한다.

### 5-1. 할 일 추가 (User Story 1)

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| A1 | `우유 사기` 입력 → **Enter** | 목록에 추가, 입력란 비워짐, 초점은 입력란에 그대로, `남은 할 일 1개` |
| A2 | 아무것도 입력하지 않고 **Enter** | 추가되지 않음, `할 일 내용을 입력해 주세요.` |
| A3 | `  책 반납하기  ` (앞뒤 공백 포함) 입력 → **추가** 버튼 | 공백 없이 `책 반납하기` 로 추가, `남은 할 일 2개` |
| A4 | `우유 사기` 를 한 번 더 추가 | 두 번째 `우유 사기` 도 추가되고 `같은 내용의 할 일이 이미 있어요. 그대로 추가했어요.`, `남은 할 일 3개` |

A7, A8 을 확인한 뒤 긴 할 일과 `<b>굵게</b> & 👍` 는 삭제 버튼으로 지운다. → 목록: `우유 사기`, `책 반납하기`, `우유 사기` (남은 할 일 3개)

## 6단계: 저장된 데이터 직접 들여다보기

앱이 데이터를 **브라우저 안(localStorage)에만** 저장하는지 눈으로 확인한다.

### 6-1. 저장 내용 보기

🌐 **브라우저 (Chrome 기준)**

1. 앱 화면에서 **⌘ + ⌥ + I** (개발자 도구)
2. 상단 **Application** 탭 → 왼쪽 **Storage › Local storage › http://localhost:8000**
3. 키 `my-todo:todos` 의 값이 보인다. (예시 — 지금까지 해 본 내용에 따라 다르다)

```json
[{"id":2,"text":"책 반납하기","completed":true},{"id":4,"text":"운동하기","completed":false}]
```

> Safari: 설정 › 고급 › "웹 개발자용 기능 보기" 켜기 → **⌥ + ⌘ + I** → **저장 공간** 탭

### 6-2. 외부로 나가는 요청이 없는지 (헌법: 개인정보 보호)

1. 개발자 도구 **Network** 탭 → 새로 고침(⌘ + R)
2. 할 일을 추가·체크·삭제해 본다.
3. ✅ 목록에 `localhost` 요청(`index.html`, `app.js`, `style.css` …)만 있고 **다른 주소로 가는 요청이 없다.**

### 6-3. 저장 데이터가 깨졌을 때 (User Story 3 예외 상황)

**Console** 탭에서 입력:

```js
localStorage.setItem('my-todo:todos', 'abc'); location.reload();
```

✅ 앱이 멈추지 않고 빈 목록으로 시작하며 `저장된 목록을 읽을 수 없어 빈 목록으로 시작해요.` 가 보인다.

### 6-4. 할 일 500개로 속도 확인 (성공 기준 SC-003)

**Console** 탭에서 입력:

```js
localStorage.setItem('my-todo:todos', JSON.stringify(
  Array.from({ length: 500 }, (_, i) => ({ id: i + 1, text: `할 일 ${i + 1}`, completed: i % 3 === 0 }))
)); location.reload();
```

✅ 추가·체크·삭제·보기 전환이 눈에 띄는 지연 없이 동작한다. `남은 할 일 333개` 가 보인다.

### 6-5. 데이터 초기화 (처음 상태로)

**Console** 탭에서 입력:

```js
localStorage.removeItem('my-todo:todos'); location.reload();
```

✅ `아직 할 일이 없어요. 첫 할 일을 추가해 보세요.`, `남은 할 일 0개` 로 돌아온다.

## 7단계: 명세와 다를 때 고치기

5·6단계에서 다르게 동작한 것이 있으면, **무엇이 기준인지 먼저 판단**한다.

| 상황 | 기준 | 할 일 |
| --- | --- | --- |
| 명세(spec.md)는 맞는데 앱이 다르게 동작 | **명세** | 코드 수정 요청 → `/speckit-converge` 로 재검증 |
| 앱 동작이 오히려 맞거나, 새로 정할 것이 생김 | **새 결정** | 명세부터 수정 → plan/tasks 갱신 → implement ([GUIDE.md 7단계 규칙](GUIDE.md#7-단계-구현implement과-수렴converge)) |

🤖 **Claude Code** — 코드가 명세와 다를 때

```text
앱을 직접 확인해 보니 아래 동작이 specs/001-todo-list-app/spec.md 와 달라. 명세에 맞게 코드를 고치고, 이 경우를 잡아내는 테스트도 추가해 줘.
- 시나리오 D1: 할 일을 삭제한 뒤 초점이 다음 항목의 삭제 버튼으로 가지 않고 사라짐
```

수정이 끝나면:

```text
/speckit-converge
```

🤖 **Claude Code** — 명세를 바꿔야 할 때 (예: 완료된 할 일을 맨 아래로 보내고 싶다)

```text
/speckit-specify 완료한 할 일은 목록 맨 아래로 내려가도록 기존 할 일 목록 기능을 바꾸고 싶어.
```

> 작은 변경은 새 기능 폴더(002-…)로 만들어도 되고, `spec.md` 를 직접 고친 뒤 `/speckit-plan` → `/speckit-tasks` → `/speckit-implement` 순으로 갱신해도 된다.

✅ **확인**
- [ ] 수정 후 `node --test` 가 `# fail 0` 이다.
- [ ] 문제였던 시나리오를 다시 해 보니 기대대로 동작한다.
- [ ] `/speckit-converge` 가 **Converged** 를 보고했다.

## 8단계: (도전) 마감일 기능 써 보기

[GUIDE.md 8단계](GUIDE.md#8-단계-도전-두-번째-기능-추가--명세부터-다시)에서 마감일 기능(`specs/002-…`)을 구현했다면 아래를 확인한다. 서버를 다시 켜고 **⌘ + Shift + R** (강력 새로 고침)로 연다.

| # | 이렇게 해 본다 | 이렇게 되어야 한다 |
| --- | --- | --- |
| U1 | 기존에 있던 할 일 확인 | 마감일 없이 그대로 보임 (기존 데이터 호환) |
| U2 | `보고서 제출` 입력, 마감일을 **내일**로 선택 후 추가 | 할 일 옆에 마감일 표시 |
| U3 | `세금 납부` 입력, 마감일을 **어제**로 선택 후 추가 | 지난 마감으로 **눈에 띄게 표시** |
| U4 | `세금 납부` 체크 | 완료되면 지난 마감 강조가 사라지거나 약해짐 (명세에 따라) |
| U5 | 마감일 없이 `물 마시기` 추가 | 정상 추가 |
| U6 | **마감일 순 정렬** 선택 | `세금 납부`(어제) → `보고서 제출`(내일) 순, 마감일 없는 항목은 명세에 정한 위치 |
| U7 | 새로 고침 | 마감일이 유지됨 |

✅ **확인**
- [ ] U1~U7 이 모두 기대대로 동작한다.
- [ ] 6-1 방법으로 보면 `my-todo:todos` 에 마감일이 `YYYY-MM-DD` 형식으로 저장되어 있다.
- [ ] 5단계 시나리오도 다시 해 보니 그대로 동작한다. (기존 기능이 깨지지 않음)
- [ ] `node --test` 가 `# fail 0` 이다.

## 문제 해결

| 증상 | 해결 |
| --- | --- |
| 화면이 비어 있거나 버튼이 동작하지 않는다 | `file://` 로 열었는지 확인. `python3 -m http.server 8000` 실행 후 `http://localhost:8000` 으로 접속 |
| `Address already in use` | 8000 포트를 다른 프로그램이 사용 중. `python3 -m http.server 8080` 으로 바꾸고 `http://localhost:8080` 접속 |
| 코드를 고쳤는데 화면이 그대로다 | 브라우저 캐시. **⌘ + Shift + R** (강력 새로 고침) |
| 처음 열었는데 할 일이 이미 있다 | 예전에 같은 주소(localhost:8000)로 쓰던 데이터. 6-5 초기화 |
| `변경 내용을 저장하지 못했어요…` 문구가 보인다 | 브라우저가 저장을 막은 상태(시크릿 창, 저장 공간 차단 등). 일반 창에서 다시 연다 |
| 새로 고침하면 데이터가 사라진다 | 시크릿 창이 아닌지 확인. 일반 창에서도 사라지면 시나리오 번호(P1 등)와 함께 Claude Code에 수정 요청 |
| `node --test` 에서 `Cannot use import statement` | `package.json` 에 `"type": "module"` 이 있는지 확인 |
| 개발자 도구 Console 에 빨간 오류가 있다 | 오류 메시지를 복사해 Claude Code에 "브라우저 콘솔 오류야. 고쳐 줘"와 함께 붙여 넣기 |
| 화면 문구·배치가 이 문서와 다르다 | 정상이다. AI가 디자인을 정하므로 **기능(5단계 시나리오)이 같으면** 통과. 내 앱의 `specs/001-todo-list-app/quickstart.md` 기준으로 확인 |
